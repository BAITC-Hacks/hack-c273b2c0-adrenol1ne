# Оценка архитектуры до рефакторинга

Исходная версия: коммит `139c066`. Существующие учебные сценарии и расчёты сохраняются.

| Проблема                                                        | Следствие                                                    | Изменение                                                                |
| --------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------ |
| Общий каталог lib смешивал Prisma, бизнес-правила, AI и DTO     | Трудно понять ответственность файла                          | Отдельные apps/backend, packages/domain, packages/ai и packages/shared   |
| React импортировал readiness, scoreActivity и simulateWorkforce | Одни и те же правила исполнялись в браузере и сервере        | API отдаёт готовые модели представления; вычисления выполняются сервером |
| Один HTTP обработчик содержал доступ к БД и проверки прав       | Изменения разрешений затрагивали множество ветвей            | Контроллеры по ролям, общие authorization и error handler                |
| AIExplanationService сам читал и записывал Prisma               | Модель была связана с хранением                              | Чистый AI модуль; кешом управляет backend сервис                         |
| Сервисы передавали ORM запросы напрямую                         | Схема хранения просачивалась в бизнес-код                    | Репозитории с предметными операциями и транзакциями                      |
| Отсутствовали MANAGER и журнал важных действий                  | Нельзя проверить область видимости и происхождение изменений | Централизованные разрешения, связь manager-team, AuditService            |
| Разрозненные форматы ошибок и схемы запросов                    | Клиент зависел от текста ошибок                              | Общие Zod контракты и структурированный ApiError                         |

Выбран модульный монолит: одна Next.js среда выполнения, одна БД, одна команда запуска. Next route adapter — единственная точка соединения framework и backend. Отдельные сервисы, очереди и контейнеры не нужны.
